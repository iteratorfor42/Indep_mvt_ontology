## — 같은 49개 항목을 두 개의 서로 다른 검증 모델이 어떻게 다르게 기록했는가

> `independence_ontology_factcheck_v8.csv`(49행, 8개 컬럼)와
> `v9_5_claims_unified.csv`(55행, 25개 컬럼, part=core/hold/exclusion)를
> 실제 셀 값까지 대조한 결과.

---

## 1. 구조 자체가 다른 이유

| | v8 factcheck | v9.5 통합본 |
|---|---|---|
| 단위 | **항목**(인물/단체/학교/사건) 1개 = 1행 | **Claim**(개별 주장) 1개 = 1행. 항목 1개가 여러 Claim으로 쪼개질 수 있음 |
| 행 수 | 49 | 55 (49개 항목에서 파생) |
| 판정 필드 | `재검증 필요 여부` 1개(완료/권장/보류(v8)) | `claim_status`/`date_status`/`verification_status`/`review_flag` 4개 독립 필드 + `part`(core/hold/exclusion) |
| 근거 표기 | `출처(1차 확인)`에 매체명만 나열 | `source_id`/`evidence_id`로 출처와 근거 문장을 분리해 추적 가능 |
| 날짜 표기 | `확인된 사실` 문장 안에 자연어로 섞여 있음 | `date_value`/`date_precision`/`date_value_status`로 구조화 |
| 변경 이력 | `비고`에 자유서술로 누적 | `change_history`에 버전별로 append |

**v8은 "이 항목에 대해 지금까지 확인한 것"을 한 줄로 요약하는 표**이고,
**v9.5는 "이 항목에서 파생된 개별 주장 하나하나가 각각 얼마나 근거가 있는가"를 추적하는 표**.

## 4. 오산학교 — "완료" 판정의 근거가 이후에 갈라짐

**v8**: 번호 1, "1907년 12월 24일 이승훈이 … 설립", **재검증 필요 여부:
완료**. 비고에 "v6에서 …정부DB 포함 다출처 일치, 확정"이라고 명시.

**v9.5**: 이 하나의 "완료"가 **두 개의 별개 Claim**으로 쪼개져 있다.

```text
CLM-OSAN-01  subject=:이승훈  설립  object=:오산학교  1907-12(Month)   part=core
CLM-OSAN-02  subject=:이승훈  개교  object=:오산학교  1907-11-24(Day)  part=hold, review_flag=relationship_issue
```

v8이 "완료"로 못박았던 단일 날짜(1907-12-24)는, 실제로는 학교 연혁
계열 출처의 "12월"과 인물 항목 계열 출처의 "11월 24일"을 조합해 만든
값이었다는 게 v9.5 검증 과정에서 드러났다. v8의 8개 컬럼짜리 표에는
"완료"라는 판정과 그 근거가 된 날짜 하나만 남아 있어 이 내부 불일치가
전혀 보이지 않았다 — v9.5가 Claim을 쪼갠 뒤에야 비로소 드러난 문제다.
CLM-OSAN-02는 그래서 `part=hold`로 남아 있다.

## 5. 조선물산장려회 — "완료" 뒤에 숨어 있던 두 개의 미해결 지점

**v8**: 번호 11, "1920년 8월 23일 조만식 등이 평양에서 창립",
**재검증 필요 여부: 완료**.

**v9.5**: 같은 사실이 **세 개의 Claim**으로 나뉜다.

```text
CLM-JOSEON-01  1920-08(Month)     part=core        — 평양 조직, 월 단위만 확정
CLM-JOSEON-02  1920-08-23(Day)    part=exclusion   — 일자(23일) 근거 미확보
CLM-JOSEON-03  1923(Year, 서울)   part=hold         — 서울 별도 조직, 평양과 동일성 미확인
```

v8이 "완료"로 확정했던 "8월 23일"이라는 **일자 자체가 v9.5에서는
근거 없음(exclusion)으로 재분류**됐다 — v8의 판정이 v9.5 기준으로는
유지되지 못한 사례다. 게다가 v8 표에는 아예 존재하지 않던 "서울"
조직(1923년, 평양과 별개)이 v9.5에서 새 Claim으로 추가돼 있다 — v8의
평평한 "항목당 1행" 구조에서는 같은 이름의 조직이 다른 지역·다른
시점에 별도로 존재한다는 사실 자체를 담을 자리가 없었다.

## 9. v8의 "권장" 29건이 뭉뚱그리던 것을 v9.5가 세 갈래로 나눔

v8은 "권장"이라는 하나의 값으로 다음 세 가지 서로 다른 상황을 전부
같은 표시로 뭉쳐놨다.

```text
(a) 근거는 있으나 한 곳뿐이라 교차확인이 더 필요한 경우
(b) 관계·해석 자체가 불확실해 추가 검토가 필요한 경우
(c) 애초에 근거 URL 자체를 아직 못 찾은 경우
```

v9.5는 이를 구조적으로 분리한다 — (a)(b)는 `part=core`/`hold` +
`review_flag`(source_conflict/relationship_issue/provenance_gap 등)로,
(c)는 아예 `part=exclusion` + `exclusion_reason`으로 뺀다. 예를 들어
v8에서 똑같이 "권장"이었던 숭실학교(번호 3, 비고 없음)와 대성학교(번호
2, 승계관계 삭제 이력 있음)는, v9.5에서는 전자가 `exclusion`(CLM-030,
근거 URL 자체 없음), 후자가 `core`(CLM-002/011, 근거는 있으나 중복)로
전혀 다른 칸에 들어간다 — v8의 "권장" 하나로는 구분되지 않던 차이라서 이렇게 다 나눔.

## 10. 결론

| 관찰 | 의미 |
|---|---|
| v8 "완료"(19건) 중 일부가 v9.5에서 hold/exclusion으로 재분류됨(조선물산장려회 일자, 이동휘 취임 등) | v8의 "완료"는 항목 단위 확신이었지, Claim 단위로 쪼개면 유지되지 않는 경우가 있었다 |
| v8 "보류(v8)"였던 김좌진이 v9.5에서 confirmed로 뒤집힘 | 모델의 우열이 아니라 조사 범위(조직 명단만 vs 인물 항목까지) 차이 |
| v8에서는 안 보이던 중복 Claim(대성학교), 신규 Claim(조선물산장려회 서울) 등장 | 항목당 1행 구조에서는 애초에 표현 불가능했던 것들 |
| v8이 이미 남긴 미해결 메모(안악사건 관계 중복)가 v9.5에도 그대로 이월 | 스키마를 바꿔도 실제 사료 조사가 안 끝나면 문제는 승계된다 |
| v8 "권장" 29건이 v9.5에서 core/hold/exclusion 세 갈래로 갈라짐 | 세분화된 상태 모델이 실제로 다른 종류의 미확정 상태를 구분해냈다 |

**종합**: 두 표는 같은 49개 항목을 다루지만 "확인했다"는 말의 의미
자체가 다르다. v8의 "완료"는 "그럴듯한 근거를 찾았고 특별히 문제
제기가 없었다"는 뜻에 가깝고, v9.5의 `core`/`confirmed`는 "이
구체적인 한 문장 주장을 이 구체적인 근거 문장 하나가 직접 뒷받침한다"는
훨씬 좁은 의미다. 그 결과 v9.5는 v8보다 더 많은 것을 의심하게 됐고(v8
"완료" 19건 중 다수가 v9.5에서 세분화·재검토 대상이 됨), 동시에 v8이
놓쳤던 근거(김좌진)도 새로 찾아냈다 — 더 엄격한 모델이 항상 "더 적게
확정한다"는 뜻은 아니라는 것을 이 비교가 보여준다.
