# v5 검증 보고서

## — v8 추가검증보고서(ver5) 원칙을 소급 적용한 v5 TTL 감사

> 본 보고서는 v9 계열에서 확립된 "v8 추가검증보고서(ver5, 설계 승인본)"의 원칙을, v1~v8 TTL 본체의 **v5 스냅샷**에 소급 적용해 감사한다. v5는 "검토안" 대조 절차가 아직 도입되지 않은 마지막 버전이며, v6부터 시작되는 외부 검증 절차 직전의 상태를 보여준다.

---

## 0. 이 보고서가 검증하는 대상

- **입력**: 업로드된 v5 TTL(v4→v5 변경사항 changelog + 클래스/속성 정의 + 8~9절 인스턴스 데이터 전체)
- **위치**: v1~v8 TTL 본체 트랙에서 v4와 v6 사이. **아직 어떤 외부 검토안도 대조하지 않은, 편찬자 스스로의 정비만 이뤄진 마지막 시점**이다.
- **목적**: v6에서 대량으로 쏟아지는 수정("검토안 반드시수정 ①~④" 등)이 사실은 v5까지 얼마나 방치되어 있었는지를 구체적으로 드러낸다.

## 1. v5가 스스로 밝힌 변경사항

```text
hasCompiler placeholder(:김바로_예시편찬자)를 실제 편찬자 개체 :iteratorfor42로
전체 68회 일괄 치환. Person 선언의 rdfs:comment도 정정.
남은 작업: hasWebResource 항목별 실제 permalink, 시간정보 미상 52건 보강
```

### 1-1. changelog 자체의 내부 불일치

이 텍스트는 v4 changelog와 미묘하게 어긋난다. v4 항목 1번은 이렇게 되어 있다.

```text
"편찬자는 8절 예시와 동일한 :iteratorfor42 placeholder를 그대로 사용 -
 실제 연구자 본인 개체로 교체 필요"
```

즉 v4는 **`:iteratorfor42` 자체를 "아직 교체돼야 할 placeholder"**로 서술하는데, v5는 **`:iteratorfor42`를 "placeholder를 대체한 실제 개체"**로 서술한다 — 같은 URI가 두 changelog에서 정반대 역할(치환 대상 vs 치환 결과)로 등장한다. ver5 관점에서 이는 `evidence_note`(여기서는 changelog 자체)의 정합성 문제로, 사소하지만 **버전 이력 문서 자체도 재검증 대상**이라는 점을 시사한다. 실제 데이터(트리플)는 v5에서 `:iteratorfor42`로 일관되게 채워져 있어 기능적으로는 문제가 없다.

## 2. v5 시점까지 방치되어 있던 문제 (v6에서 한꺼번에 터지는 것들의 근원)

### 2-1. 오산학교-대성학교 승계관계 — 근거 없는 확정 주장

```turtle
:오산학교 :succeedByPersonTo :대성학교 ;
    :hasSpaceValue "정주"@ko .
```

이 트리플에는 별도의 `hasBibo`나 `hasWebResource`가 붙어 있지 않다. 그런데 바로 위 주석은 다음과 같이 상당히 구체적인 서사를 제공한다.

```text
"오산학교는 신민회의 노선(법률/결의)에 따라 설립되었고, 안창호가 세운
대성학교를 인물/노선상 모델로 삼음 -> succeedByPersonTo 로 표현"
```

ver5 Rule P-01("출처 URL의 존재가 곧 값의 검증을 뜻하지 않는다")을 뒤집어 적용하면 여기서는 **출처 자체가 아예 없는 상태에서 서사만으로 구조화된 관계(succession)를 단정**하고 있다. 이는 v9 계열 전체가 경계하는 "그럴듯한 서술이 곧 근거는 아니다"의 전형적 사례다.

**판정**: v5까지 아무 의심 없이 유지되다가, v6에서 "확인 가능한 자료로는 두 학교가 조직적으로 승계 관계에 있다는 근거가 없다"며 삭제된다.

### 2-2. 안명근체포 — hasEventType 자체가 틀림, 그리고 그것을 알면서 방치

```turtle
:19101101안명근체포_01 ...
    :hasEventType :임명 ;  # 원 논문 관례상 부정적 이벤트도 큰 틀에서 처리하되, 별도 유형 세분 가능
```

체포라는 사건에 `:임명`(사실상 "안명근이 임명되었다"는 의미)을 부여하고 있다. 더 중요한 것은 **이 오류가 인라인 주석으로 이미 인지되고 있었다**는 점이다 — "부정적 이벤트도 큰 틀에서 처리하되, 별도 유형 세분 가능"이라는 문구는 "지금은 틀렸지만 나중에 고치겠다"는 자기 인지다. 그러나 `:체포`라는 Term은 이 시점 사건유형 시소러스(§6)에 아직 존재하지 않는다 — 문제를 알면서도 고칠 어휘 자체를 만들지 않은 상태다.

**판정**: v6에서야 `:체포` Term이 신설되고 이 Event의 `hasEventType`이 정정된다. 참고로 `hasTimeValue`도 이 시점엔 "1910-11-01"(±10일)로, v6에서 재검증되는 "1910-12-01"(±1개월)과도 다르다 — 유형과 날짜 둘 다 잘못된 채로 v5까지 남아 있었다.

### 2-3. 사건 확대 구조 — 안악사건이 선언만 되고 실제로는 건너뛰어짐

§9에 `:안악사건 rdf:type :Event`가 선언되어 있고 `hasTimeValue "1910-01-01"`(placeholder)까지 부여되어 있다. 그런데 실제 확대 사건 체인은 다음과 같다.

```turtle
:19110101백오인사건확대_01
    :hasPreObject :19101101안명근체포_01 ;   ← 안명근체포에서 곧바로
    :hasPostObject :백오인사건 ;              ← 백오인사건으로 직행
```

**`:안악사건`이라는 Event가 선언은 되어 있으면서도 이 인과 체인 어디에도 연결되어 있지 않다** — 이름만 있고 그래프상 고립 노드에 가깝다.

**판정**: v6에서 `:안악사건확대_01`이라는 중간 단계 Event가 신설되며 `안명근체포 → 안악사건확대 → 안악사건`, `안악사건 → 백오인사건확대 → 백오인사건`의 2단계 구조로 비로소 실제 연결된다.

### 2-4. 역사적 사건 6개 전부 — 추정 플래그 없는 sentinel 날짜

§9의 역사적 사건 노드 6개(삼일운동·안악사건·백오인사건·봉오동전투·청산리전투·물산장려운동) 전부 다음과 같은 패턴이다.

```turtle
:삼일운동 :hasTimeValue "1919-01-01"^^xsd:dateTime .   ← hasEestimation 없음
:봉오동전투 :hasTimeValue "1920-01-01"^^xsd:dateTime .  ← hasEestimation 없음
```

`hasEestimation` 속성 자체가 **아예 부여되지 않았다**. ver5/v6이 나중에 확립하는 원칙 — "연/월 단위까지만 확인된 경우 대표 날짜를 sentinel로 넣지 않는 것이 원칙이며, 부득이하게 넣는 경우 반드시 hasEestimation과 범위값을 함께 채운다" — 을 기준으로 보면, v5는 이 원칙이 **아직 성문화되기 전이라 원칙 위반이라는 인식조차 없는 상태**다. 6건 모두 "1월 1일"이라는 명백한 placeholder를 마치 확정값처럼 놔두고 있다.

**판정**: v6에서 삼일운동(1919-03-01, 확정)·봉오동전투(1920-06-07)·청산리전투(1920-10-21)가 실제 날짜로 교정되고, 안악사건·백오인사건·물산장려운동은 최소한 `hasEestimation "1"` 플래그가 부여된다.

### 2-5. `:확대2` — 의미 중복 Term이 아직 존재

```turtle
:확대2 rdf:type :Term .
```

`:확대`와 별도로 `:확대2`가 선언되어 있다. v6 changelog는 이를 "3회차에서 이미 삭제하고 통일한 것을 유지함"이라고 언급하는데, **v5에는 아직 그 정리가 되어 있지 않다** — 즉 이 중복은 v5→(비공개 3회차)→v6 사이 어느 지점에서 해소된 것으로 보이며, v5 자체는 여전히 두 개의 사실상 동의어 Term을 갖고 있다.

**판정**: v5에는 존재, v6 시점엔 이미 정리된 상태로 넘어감(문서화되지 않은 중간 작업).

### 2-6. 스키마 정의 수준의 comment 미비

| 속성 | v5 comment | v6 이후 |
|---|---|---|
| `hasObject` | "사건의 주체" | "사건의 핵심 참여자 또는 변화의 중심 대상"(체포·해임처럼 대상이 행위자가 아닌 경우 포괄) |
| `hasBT` | "상위어" (방향 불명, `owl:inverseOf` 없음) | "현재 용어보다 상위인 개념(Broader Term)", `owl:inverseOf hasNT` 추가 |
| `hasTimeEestimationRangeValue` | comment 없음 | "hasTimeValue를 중심으로 한 시간 추정 오차의 크기" 등 의미 명시 |
| `hasFoundedYear` | §4(조직모델)가 아니라 §9(인스턴스 절) 안에 뒤늦게 선언, comment 없음 | §4로 정리, "설립 행위는 별도 Event로, 이 값은 그 요약" comment 추가 |

**판정**: 전부 v6에서 정비된다. 특히 `hasFoundedYear`가 스키마 정의부(§4)가 아니라 인스턴스 데이터부(§9)에 끼워져 있는 것은 문서 구조 자체의 정리가 안 된 상태를 보여준다.

## 3. v5가 이미 잘하고 있던 것

- **중복 개체 제거**: `:이승훈설립오산학교_01`(시간정보 없음)과 `:19071201이승훈설립_01`(시간값·추정범위·출처 완비)이 같은 사실을 가리키는 것을 발견해 후자만 남긴 것 — leaf node라 참조 무결성이 깨지지 않음을 확인한 후 병합했다는 점에서 신중한 절차를 거쳤다.
- **천도교 3건 "재검증 권장" 표시**: 손병희·오세창·최린 소속 이벤트에 이미 "다른 항목과 동일한 신뢰수준으로 취급하지 말 것"이라는 경고를 코멘트로 남겨두었다 — 이는 v9 계열의 review_flag 개념을 가장 초기 형태로 선취한 것이다.
- **hasCompiler 일괄 치환의 규모 명시**("68회")는 이후 v9 계열의 "지표를 구체적 숫자로 남긴다"는 관행과 맥이 닿는다.

## 4. 세부 판정표

| 항목 | v5 상태 | 문제의 성격 | 해소 시점 |
|---|---|---|---|
| 오산학교-대성학교 succeedByPersonTo | 근거(hasBibo) 없이 서사만으로 단정 | ver5 Rule P-01 위반 | v6 |
| 안명근체포 hasEventType | `:임명`으로 오분류, 스스로 인지하고도 방치 | 오류를 알고도 어휘 미비로 미수정 | v6(`:체포` Term 신설) |
| 안명근체포→백오인사건 확대구조 | 안악사건이 선언만 되고 인과체인에서 누락 | 선언된 개체와 실제 그래프 연결의 불일치 | v6(2단계 구조 신설) |
| 역사적 사건 6건 날짜 | 전부 hasEestimation 없이 1월 1일 sentinel | 원칙 성문화 이전이라 위반 인식조차 없음 | v6(3건 확정, 3건 플래그 부여) |
| `:확대2` 중복 Term | 존재 | 시소러스 정합성 문제 | 비공개 중간 작업에서 해소 |
| hasObject/hasBT 등 comment | 방향·범위 불명확 | 스키마 문서화 미비 | v6 |
| hasFoundedYear 배치 | §9(인스턴스)에 끼워 선언 | 문서 구조 미정리 | v6(§4로 정리) |

## 5. 결론

| 영역 | 판정 |
|---|---|
| hasCompiler 치환(68회) | 완료, 다만 v4/v5 changelog 간 서술 불일치 존재 |
| 오산-대성 승계관계 | **미검증 상태로 방치** — 근거 없이 서사만으로 확정 |
| 안명근체포 유형/날짜 | **알려진 오류를 어휘 부재로 방치** |
| 사건확대 2단계 구조 | **미구현** — 중간 노드가 선언만 되고 고립됨 |
| 역사적 사건 날짜 | **원칙 부재로 sentinel 방치**, 문제 인식조차 없었음 |
| 천도교 3건 재검증 표시 | 선제적 조치 — v9 review_flag 개념의 초기 형태 |

**총평**: v5는 "검토안"이라는 외부 대조 절차가 도입되기 직전의 상태로, 스스로 인지한 문제(안명근체포 유형 오류)조차 고칠 어휘가 없어 방치하고, 인지하지 못한 문제(승계관계 근거 부재, 사건확대 구조 미완성, 날짜 sentinel)는 훨씬 많다. v6이 "3회차 검토안"을 받고 나서야 이 문제들이 한꺼번에 터져 나온 것은, v5까지는 **편찬자 본인의 자기 점검만으로는 이런 유형의 문제를 발견하기 어려웠다**는 것을 보여준다 — 이는 이후 v9 계열 전체가 왜 "외부 검증 트랙"으로 발전했는지에 대한 가장 이른 시점의 정황 증거이기도 하다.
