# v6 검증 보고서

## — v8 추가검증보고서(ver5) 원칙을 소급 적용한 v6 TTL 감사

> 본 보고서는 v9 계열에서 확립된 "v8 추가검증보고서(ver5, 설계 승인본)"의 원칙을, 그 원칙이 아직 존재하지 않았던 시점의 산출물인 **v1~v8 TTL 본체의 v6 스냅샷**에 소급 적용해 감사한다. v6은 "3회차 검토안"이라는 외부 대조 문서를 처음으로 도입한 버전이며, v7·v8·v9 전체 검증 계보의 출발점에 해당한다.

---

## 0. 이 보고서가 검증하는 대상

- **입력**: 업로드된 v6 TTL(v4→v5→v6 변경사항 changelog + 클래스/속성 정의 + 8~9절 인스턴스 데이터 전체)
- **위치**: v1~v8 TTL 본체 트랙에서 v5와 v7 사이. **날짜·관계 정보가 대량으로 채워지기 이전, 처음으로 "검토안" 대조 절차가 도입된 시점**이다.
- **목적**: v6이 무엇을 처음 고쳤고, 무엇을 아직 인지조차 못 하고 있었는지를 ver5의 언어로 정리한다. 이 보고서는 v7 검증보고서와 쌍을 이루며, "v6→v7 사이에 실제로 무엇이 늘어났는가"를 대조하는 것이 핵심이다.

## 1. v6이 스스로 인지하고 고친 것 (필수 수정 4건)

```text
① 안명근체포: hasEventType :임명→:체포 정정 확인, hasTimeValue 1910-11-01→1910-12-01(±1개월)
② 오산학교-대성학교 succeedByPersonTo 삭제 (병렬 설립으로 재해석)
③ 오산학교 개교일: 1907-12-01(추정)→1907-12-24(확정, hasEestimation 0)
④ 안명근체포→백오인사건 단일 확대를, 안명근체포→안악사건→백오인사건 2단계로 재구성
```

이 중 ③은 이후 v9 검증 트랙에서 정면으로 재검토되는 대목이므로 §3-1에서 별도로 다룬다.

## 2. v6이 강하게 권장받아 반영한 것 (④건)

`hasObject` comment 수정("사건의 주체"→"핵심 참여자 또는 변화의 중심 대상"), `hasPreObject`/`hasPostObject` comment에 "관련 사건" 포함, `hasBT owl:inverseOf hasNT` 추가 및 comment 명확화, `hasFoundedYear`/`hasTimeValue`/`Group` 클래스 comment 보강 — 전부 **스키마(클래스·속성 정의) 수준의 정비**이며, 인스턴스 데이터 자체의 정확성과는 별개다.

## 3. 세부 진단 — v6 시점의 문제

### 3-1. 오산학교 개교일 "확정"의 근거 자체가 약함

v6은 "독립운동인명사전·위키백과·나무위키 등 복수 출처를 대조한 결과 1907년 12월 24일로 일치"했다며 `hasEestimation "0"`(확정)을 부여했다. ver5 §4-2 기준으로 이 판단을 재구성하면 문제가 보인다.

```text
:19071224이승훈설립_01
    hasEventType = :설립         ← 유형은 "설립"
    comment      = "...개교일을 수정..."  ← 서술은 "개교"
```

**유형(설립)과 서술(개교)이 v6 시점부터 이미 하나의 Event 안에 섞여 있다.** v6은 "3회차 검토안이 11월 24일이라고 주장했으나 채택하지 않았다"고 명시하는데, 이는 v6이 이미 상충하는 값을 인지하고도 "복수 출처 일치"를 근거로 자신의 값을 우선시했다는 뜻이다. ver5 Rule P-04("출처 간 충돌은 삭제하지 않고 provenance에 보존한다")를 적용하면, v6처럼 한쪽 값을 채택하고 다른 쪽을 폐기하는 것이 아니라 **두 값 모두를 서로 다른 Claim으로 보존**했어야 한다. 실제로 v9 ver2가 「이승훈」 항목 원문을 다시 열었을 때 "11월 24일"이 확인되면서, v6의 "확정" 판정 자체가 재조정된다.

**판정**: v6은 이 문제를 인지했지만("검토안의 해당 주장은 채택하지 않고") 잘못된 방향으로 해소했다 — 상충값을 지우고 하나만 남기는 방식. 이는 v7에서도 그대로 유지되고, v9 계열에 가서야 Claim 분해로 바로잡힌다.

### 3-2. 소속/참여 Event — 시간정보가 전면적으로 비어 있음

v6의 9-6~9-17절을 전수 확인하면, 다음 Event들이 **전부 `hasTimeValue` 없이 "시간정보 미상" 코멘트만** 달려 있다.

```text
신민회 소속: 이승훈, 안창호, 양기탁, 최광옥, 이종호, 이회영, 이시영 (7건)
임시정부 소속: 안창호, 이시영, 이동녕, 이승만, 이동휘 (5건)
3·1운동 참여: 이승훈, 조만식, 손병희, 이종일, 한용운, 오세창, 최린, 정춘수, 박희도 (9건)
```

v6 changelog에는 이 12+9건에 대한 언급이 전혀 없다 — v6은 이 공백을 "아직 손대지 못한 것"으로 명시조차 하지 않았다. ver5 관점에서는 `date_status`가 사실상 `not_directly_verified`도 아니고 **필드 자체가 부재**한 상태다.

**판정**: v6에서는 문제로 식별되지 않았다. 이 공백을 실제로 메우는 것이 v7의 핵심 작업(신민회 7건 Year 추정, 임시정부 5건 Year 추정, 3·1운동 6건 확정+3건 예외)이었다 — 즉 v6→v7 사이의 가장 큰 변화는 "오류 수정"이 아니라 **"빈 칸 채우기"**였다.

### 3-3. 이종일-보성학교 — v6은 문제 자체를 인지하지 못함

v6의 `:이종일경영보성학교_01`은 다음과 같다.

```text
hasPostObject = :보성학교
comment       = "시간정보 미상. 후속 조사로 hasTimeValue 및 추정모델 보강 필요."@ko
```

v7 검증보고서에서 지적한 "코멘트가 데이터를 정정하는" 문제(코멘트는 보성사라고 말하는데 데이터는 보성학교인 상태)는 v6에는 **아직 존재하지도 않는다** — v6의 코멘트는 그저 "시간정보 미상"일 뿐, 보성사와 관련된 서술 자체가 없다.

**판정**: v6은 이 문제를 인지조차 못했다. v7이 국회도서관/Encyves Wiki를 재검색해 처음으로 "보성사" 문제를 코멘트에 남겼고(그러나 데이터는 미수정), v8에서야 `:보성사` Group 신설로 실제 해결된다. 즉 3단계(v6 미인지 → v7 인지만 → v8 해결)를 거친 사례다.

### 3-4. 신흥무관학교 — "공동설립" 개념 자체가 아직 없음

v6의 사건유형 시소러스(§6)에는 `:설립`, `:임명`, `:해임`, `:전향`, `:확대`, `:소속`, `:체포`, `:일반임명`, `:피포상철회`만 있고 **`:공동설립`은 존재하지 않는다.** 이회영·이시영·이동녕·이상룡 4인의 신흥무관학교 설립 Event는 전부 `hasEventType :설립`으로 개별 표시되어 있고, 4인이 함께 설립했다는 것을 표현할 방법 자체가 없다.

**판정**: v6에는 이 문제의 존재조차 인지되지 않았다. v7이 "문서20 5·6번"이라는 외부 개선안을 받아 `:공동설립` Term을 신설하면서 처음 해결한다.

### 3-5. 김좌진-신민회 — "재검증 권장" 경고 자체가 없음

v6의 `:김좌진소속신민회_01`은 다음과 같다.

```text
comment = "시간정보 미상. 후속 조사로 hasTimeValue 및 추정모델 보강 필요."@ko
```

v7·v8에서 등장하는 "신민회 공식 명단에 김좌진이 없다"는 재검증 경고가 v6에는 **전혀 없다.** 다른 소속 Event들과 똑같이 "시간정보 미상"이라는 일반 문구만 달려 있어, 이 관계가 다른 신민회 소속 관계들과 다를 바 없는 수준의 신뢰도로 취급되고 있었다.

**판정**: v6 시점에는 관계 자체의 신뢰도 문제가 전혀 식별되지 않은 상태. v7이 신민회 공식 명단을 직접 대조하면서 처음 발견하고, v8이 `hasValidationStatus`로 격리하며, v9 ver4가 반대로 confirmed 근거를 찾아낸다 — 4단계(v6 무인지 → v7 발견 → v8 격리 → v9 정정)를 모두 거친, 이 프로젝트 전체에서 가장 긴 이력을 가진 사례다.

### 3-6. v6이 의도적으로 보류한 것 — 판단은 대체로 타당

```text
- 최린 "임명→전향" 분리: 근거 없이 나누지 않음 (ver5 원칙과 일치)
- 신흥강습소→신흥무관학교 승계 모델링: 별도 조사 필요 (v8에서 실제로 진행, 이때는
  "날짜 수정"이 아니라 "실체 분리"가 필요하다는 것을 v6은 예상하지 못함)
- hasEvidenceStatus 등 검증상태 property 신설: "검토안도 필수 아니라 판단" —
  그러나 실제로는 v8에서 hasValidationStatus로, v9에서 4개 독립 필드로 발전하며
  프로젝트의 핵심 인프라가 된다. v6의 "필수 아님" 판단은 결과적으로 과소평가였다.
- hasWebResource/hasBibo 타입 변경: 원 논문 모델 유지가 목표라 보류 — 이 판단은
  v9까지도 유지된다(v9는 원 논문과 무관한 별도 스키마이므로 이 보류 자체가 무의미해짐).
```

## 4. 세부 판정표

| 항목 | v6 상태 | v6의 인지 여부 | 실제 해소 시점 |
|---|---|---|---|
| 오산학교 개교일 "확정" | 상충값 인지 후 한쪽만 채택 | 인지함(그러나 잘못 해소) | v9 ver2~ver4 |
| 신민회/임시정부 소속 12건 시간정보 | 전부 공란 | **미인지**(언급 자체 없음) | v7 |
| 3·1운동 참여 9건 시간정보 | 전부 공란 | **미인지** | v7(6건 확정+3건 예외) |
| 이종일-보성학교/보성사 | 문제의 존재 자체가 코멘트에 없음 | **미인지** | v7(인지만), v8(해결) |
| 신흥무관학교 4인 공동설립 | `:공동설립` Term 자체가 없음 | **미인지** | v7 |
| 김좌진-신민회 신뢰도 문제 | 다른 소속 Event와 동일 취급 | **미인지** | v7(발견), v8(격리), v9(정정) |
| hasEvidenceStatus류 속성 신설 보류 | "필수 아님"으로 판단 | 인지 후 과소평가 | v8(hasValidationStatus), v9(4필드) |

## 5. 결론

| 영역 | 판정 |
|---|---|
| 필수 수정 4건 | 완료(단, ③ 오산학교 개교일은 해소 방식 자체가 이후 재검토 대상이 됨) |
| 강력권장 4건(스키마 comment 보강) | 완료 |
| 소속/참여 Event 시간정보 12+9건 | **미착수 — v6 changelog에 언급조차 없음** |
| 이종일-보성사, 신흥무관학교 공동설립, 김좌진 신뢰도 | **문제로 식별조차 되지 않은 상태** |
| hasEvidenceStatus류 검증상태 속성의 필요성 | 과소평가됨 — 이후 프로젝트의 핵심 인프라가 됨 |

**총평**: v6은 "검토안과 대조한다"는 절차를 처음 도입한 버전이지만, 그 절차가 실제로 다룬 범위는 소수의 날짜·관계 정정(4건)과 스키마 comment 보강(4건)에 그쳤다. v6 changelog가 스스로 "미해결"이라고 표시한 항목이 전혀 없다는 점이 오히려 특기할 만하다 — v7이 자신의 미해결 목록을 명시적으로 남긴 것과 대조적으로, v6은 자신이 다루지 않은 12건 이상의 시간정보 공백과 3~4건의 구조적 문제(보성사, 공동설립, 김�좌진 신뢰도)를 문서화하지 않은 채 넘어갔다. 이는 v7 검증보고서의 결론("자체 changelog의 자기인지만으로는 구조적 문제를 다 잡아낼 수 없다")이 v6에는 한 단계 더 강하게 적용된다는 뜻이다 — v6은 **모르는 것을 모른다고도 말하지 않은** 버전이었다.
